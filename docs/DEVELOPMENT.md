# 开发与验证说明

当前代码处于 v0.6.0-dev 开发阶段，不能用于生产 VPS。默认菜单可做只读查询；系统修改代码仅在显式传入 `--experimental`（或菜单内输入 `ENABLE`）时可选用，并且还要求 Ubuntu / Debian、root、交互式终端及逐次确认。演示模式始终不运行操作。

## 导航和状态约定

主菜单固定为六组：系统与软件、SSH 与安全、代理服务、网络与调优、诊断与测试、工具维护与恢复。首页首次进入与 `R` 刷新时采集只读摘要，显示采集时间；返回首页复用缓存。`M` 切换模式；带模块状态的子菜单自动显示短摘要，`S` 查看详细状态，成功操作后刷新对应模块。诊断与测试、第三方测试、工具维护与恢复不提供 `S`；诊断选项 1 进入按编号选择的状态查询菜单。完整状态报告及主动探测集中在诊断模块，外部脚本单独放在其子菜单。

界面复用结构化只读检查；不同视图的采集时刻可能不同，不能把旧缓存当作修改后的验证。未知、无权限和缺少依赖不能被概括成“正常”。首页刷新和模块摘要不运行 ICMP、测速或外部脚本，也不能用服务 active 代替公网/协议验证。命令行 section、别名以及 JSON schema 不随此次菜单调整改变，`status network` 仍是 BBR + 调优 + Hy2。

维护模块中的“恢复”是现有能力说明；本轮没有初始化向导、统一变更历史或跨模块一键恢复。功能实现、前置检查、确认和恢复规则继续由各操作模块负责。

## 软件管理试验范围

- 可选：更新现有 APT 软件源索引、升级已安装的软件包、安装预设的基础 / 网络 / 查看 / 安全工具。
- 不修改软件源配置，不执行 `full-upgrade`、`autoremove` 或包卸载；安装和升级通过 `--no-remove` 在需要删除软件包时中止。
- 升级和安装先执行 APT 的模拟模式，模拟不持锁，实际执行时系统状态可能已变化。APT 或已有配置的钩子可能产生额外影响；用户取消时不执行正式修改。
- 网络目标取决于现有软件源、APT 配置、代理和重定向。界面只显示默认源文件中可识别的 HTTP(S) 主机，省略 URL 凭据和路径；它不能证明显示了所有目的地。
- 不继承 `APT_CONFIG`，避免调用者改变 APT 的配置目录、钩子和来源；代理变量会保留但不显示。
- 软件包升级无法保证回滚。APT 退出码为 0 不证明所有源都已成功刷新、所有服务正常或不需要重启。

## 其他试验功能的边界

- **3x-ui：**固定官方版本和安装脚本摘要，现有安装会被拒绝覆盖。上游脚本会执行 root 操作并查询公网 IP；证书等可选步骤有额外网络与信任边界，见 [接入记录](3X-UI-AUDIT.md)。只读取面板端口/路径，不读取账户、密码或数据库。
- **BBR / fq：**仅写入项目专属 sysctl 文件，记录原值，发现冲突或外部修改时停止。内核尚未列出 `bbr` 时会先说明并在用户确认后尝试加载 `tcp_bbr`，需要时写入 `/etc/modules-load.d/vps-script-bbr.conf`；模块不会自动卸载。重启后的生效情况未验证。
- **SSH：**只处理标准 `sshd_config.d` 布局，遇到 `Match`、其他 Include、已有多因素认证或不可判断的设置会停止。新增端口先保留旧端口；可在修改前请求 UFW 放行新端口；只有旧端口由本项目管理、当前连接使用其他端口时才能尝试关闭。仅公钥认证会影响所有账户，菜单会列出可登录账户并要求输入 `ALL USERS`；当前只验证执行账户的公钥，其他账户需自行确认。 如果选择保留 root + 22，只执行“仅公钥认证”，不执行端口变更；工具不会自动禁用 root，也不会把 `PermitRootLogin yes` 改成 `prohibit-password`，但密码/键盘交互关闭后 root 实际只能使用密钥。
- **UFW：**首次启用前要求默认入站策略为 `deny`，并为当前 SSH 端口添加允许规则；遇到其他防火墙服务、现有 nftables 规则或挂钩链、无法识别的 nftables 对象时停止。超时后会尝试恢复到此前未启用状态，但预先加入的允许规则会保留；如果启用过程中断而状态快照未完成、规则被其他工具修改或恢复命令失败，自动恢复可能不执行或失败。
- **Fail2ban：**为 SSH 创建项目专属 jail，已有系统 `sshd` jail 不被覆盖；UFW 已启用时优先使用 `ufw` 封禁动作。SSH 端口变化后只更新项目 jail 的 `port` 行；实际日志匹配、封禁和解封需单独测试。
- **Hy2：**只管理项目专属 nftables 表和 systemd 单元；发现已有 NAT 规则、旧版 NAT 表或 UDP 监听冲突时停止。可选在 UFW 已启用时放行 UDP 范围和目标端口；不会修改云防火墙或客户端。应用失败时会尝试清理项目文件/规则，无法确认时保留状态供人工恢复。
- **内核网络调优：**只写 `/etc/sysctl.d/91-vps-script-tuning.conf` 和项目状态文件；不改 BBR/default_qdisc、不换内核、不做 qdisc/HTB 整形、不改 initcwnd/DNS/转发/RPS/MSS。保守/代理/缓冲三档；缓冲档按内存和用户输入的预期带宽/RTT 估算，不是实测。其他 sysctl 文件设置不同值时会停止；应用失败按快照回滚，外部修改后拒绝恢复；配置尚未生成的部分应用可根据有效快照重试恢复。切换档位或参数需先恢复旧调优。参数改变不代表性能一定提升。
- **测试与体检：**内置机器/网络/线路/带宽测试只运行固定命令；带宽测试使用 Cloudflare 单线程下载并明确消耗流量。外部 NQ/TQ/IPQuality/NetQuality/YABS 不在本项目源码内，按各自许可证运行；固定 URL 白名单、下载到临时文件、显示 SHA 和前 120 行、需要修改模式和 `RUN` 确认。上游脚本/rootfs/二进制未固定摘要，可能安装软件、访问大量第三方节点并上传 IP/结果；只在测试 VPS 使用。
- **swap / 时区：**swap 只管理 `/swapfile-vps-script` 和带标记的 fstab 行，已有其他 swap 时停止；时区只调用 `timedatectl set-timezone`，不会修改 NTP/时钟。DNS 仅只读展示。

例如，在已准备好控制台恢复、快照和测试网络的**可丢弃测试机器**上，开发者可以启动试验模式：

```bash
./vps-admin --experimental
```

该命令本身打开菜单；选择实际操作并确认后才会运行。不要在重要 VPS 上测试。

## 现有备份与恢复覆盖

当前代码没有“每次危险操作都自动做完整备份”的统一机制。需要区分以下几类证据：操作前原值、事务记录、模块资源清单、可用的恢复材料和服务商整机快照；文件存在或恢复函数返回成功，也不能替代实际连接/服务验证。

| 模块 | 当前保存或保护的内容 | 可恢复范围与限制 |
| --- | --- | --- |
| SSH | `/var/lib/vps-script/ssh-transactions/` 内记录项目 drop-in 修改前内容/权限、前后摘要、服务信息与独立回滚脚本 | 对本次项目配置进行失败/180 秒超时恢复；不是完整 `/etc/ssh` 备份，不保证跨重启，没有统一历史回退菜单；必须验证第二个 SSH 会话 |
| UFW | `ufw-transactions/` 记录首次启用事务和启用后状态摘要，先放行当前 SSH 端口 | 仅在条件匹配时尝试回到原先 inactive 状态；不是完整规则快照。预先添加的允许规则保留，状态摘要未写成、外部变化或重启可能导致不能恢复；普通端口增删没有规则备份/撤销历史 |
| BBR / fq | `bbr-state.json` 保存受管理 sysctl 原值，校验项目配置与模块持久化文件 | 模块“恢复”撤回对应参数和项目文件，不自动卸载内核模块，不恢复其他服务/内核；外部修改时停止 |
| 内核调优 | `tuning-state.json` 在写运行值前保存原值、目标值和方案，管理专属 sysctl 文件 | 应用失败尝试恢复，未完成操作可凭有效记录重试；有外部修改则拒绝覆盖。成功恢复后清理状态，不是长期历史 |
| Hy2 跳跃端口 | `hy2-state.json`、项目 nftables 表与 systemd 单元内容/摘要 | 只清理或移除项目自有转发与服务；不安装/回退 Hy2 服务端，不改客户端，不撤回 UFW/云防火墙放行 |
| swap | 标记 `/swapfile-vps-script` 与自身 fstab 行，写入时校验 fstab 未被并发修改 | 创建失败尝试清理、移除时只处理项目资源；没有完整 fstab 历史或磁盘快照，不能恢复业务数据 |
| Fail2ban | 创建或刷新项目 jail 时在内存中保留本次操作需要的配置内容 | 测试/重载失败尝试撤回本次配置；不覆盖系统 jail，没有持久备份历史或统一撤销入口 |
| 时区 | 显示当前值，调用 `timedatectl set-timezone` | 未自动记录旧时区；需事先记下并按需手动重新设置。DNS 当前只读 |
| 工具升级 | 同次事务中暂存旧程序目录、启动器及权限，失败时按身份检查恢复 | 失败保留材料并报告路径；成功后清理暂存，不形成可选历史版本；不会恢复 `/etc`、`/var` 中的系统配置 |
| APT / 3x-ui / 外部脚本 | 模拟或来源/影响说明、确认；第三方代码有自身行为 | 没有可保证的完整回滚。执行前使用服务商快照或独立备份，并准备控制台；不能用状态文件替代整机保护 |

危险操作前自动备份值得作为下一阶段重点，但必须先说明备份包含什么、不能恢复什么，并确认备份本身成功。后续拟统一受限目录、事务元数据、完整性验证、失败保留、恢复前冲突检查与保留策略，再增加历史界面和初始化向导；当前没有实现这些统一能力。详细顺序和验收条件见 [下一阶段计划](PLAN.md#下一阶段备份与初始化计划)。

## 本地测试

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
```

测试中的 APT、SSH、防火墙、Hy2 和 swap 调用使用模拟对象，不运行真实的系统软件修改，不访问软件源。安装器事务直接在临时目录测试文件切换、回滚和锁，不使用开发机的安装目录。启动脚本和演示模式可以在 macOS 上验证；实际 Linux 只读检测、系统修改和服务行为需在相应环境另行验证。

导航回归应覆盖六个入口、子菜单返回、`M`/`R`、只读模式与演示模式、外部测试子菜单，以及旧命令/JSON 兼容性。纯粹查看状态不得触发任何变更或公网探测。

## 自动检查

GitHub Actions 在 Ubuntu 虚拟机及 Debian 容器中运行单元测试与只读系统查询，结果以对应提交的运行记录为准。这些测试以模拟为主；Debian 容器不能证明 systemd、SSH、防火墙、重启持久化或跨网络协议可用。高风险功能需要带有控制台访问的独立虚拟机和 VPS 端到端测试。
