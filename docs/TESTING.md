# 隔离环境与测试 VPS 验证计划

当前本地测试不代表真实 Linux、防火墙、SSH 或 Hy2 端到端通过。在以下各阶段通过并记录结果之前，系统修改功能应继续视为试验功能，不得用于重要服务器。

## 测试环境

1. 使用可丢弃、可通过服务商控制台恢复的 VPS 或完整 Linux 虚拟机；确认没有需要保留的业务。使用快照前了解服务商的容量、费用和恢复方式。
2. 记录发行版和版本、架构、内核、虚拟化类型、systemd、可用内存与磁盘空间。逐项检查当前 SSH 会话、云防火墙、UFW / nftables / iptables 和相关服务；未知项标记为未知。
3. 先测试至少一个 Ubuntu 和一个 Debian 的明确版本；其他版本和 CPU 架构必须另行验证。容器可辅助检查语法和包管理，但不能替代完整 systemd、内核防火墙和重启测试。
4. 准备两个独立 SSH 会话和服务商控制台。第二次连接禁用 SSH 复用并核对主机密钥；不接受未解释的指纹变化。

最初的系统识别在**测试 VPS 的 SSH 终端**执行，只需提供发行版信息，不要发送密码、私钥、订阅链接或面板凭据：

```bash
cat /etc/os-release
```

确认输出后，再按需要单独检查架构与网络状态，避免一次执行未经核实的初始化命令。

记录完整发行版版本，不用“Ubuntu 26”等简称代替实际输出。安装器的前置检查与事务应在目标发行版、系统 Python 和文件系统上分别验证：当前事务使用 Python 标准库及 Linux `renameat2` 的禁止覆盖重命名，失败后必须保留仍需恢复的材料。Ubuntu 的 SSH socket 激活也需要单独实测。

临时目录测试验证安装事务的复制、发布、锁和失败恢复；CI 的一次性 Ubuntu 运行环境另行测试当前提交构包后的实际安装/升级。两者都不能替代目标 VPS 的 SSH、系统服务和网络验收。

## v0.9.0-dev 安全衔接与检查验收

先在本地运行 `python3 -m unittest discover -s tests -v`；模拟测试不改本机 SSH/防火墙，也不下载病毒库或启动真实扫描。一次性安装 CI 增加已安装路径的 `audit --demo --json` 与 `scan --demo` 验证。

在可丢弃 VPS 分别验收：

| 项目 | 通过条件 |
| --- | --- |
| UFW 故障回退 | 在控制台可恢复的实验环境模拟启用后状态读取/摘要保存失败；核对原定时器与立即恢复，检查实际 UFW inactive、新 SSH 连接及留存规则。不得在唯一连接上制造故障 |
| UFW 配置差异 | IPv6 开/关分别验证当前日志级别保持、两个 user rules 文件规范化后指纹一致；外部改动时拒绝回退并提示人工核实 |
| 旧事务重入 | 子进程中断后旧定时器仍在时，不得把“配置已存在”报为完成；audit/status 显示未结束，访问变更/恢复停止，原 worker 完成后允许继续 |
| 部分完成 | SSH 主操作完成但 Fail2ban 附属预检/备份失败、Hy2 主操作完成但 UFW 失败，向导停留本步且列出已有记录，不自动重跑主操作 |
| 恢复依赖 | UFW 启用后配置/运行 Fail2ban，再尝试恢复原 UFW 启用记录，必须拒绝关闭，不改变已有防护 |
| 轻量体检 | 比对当前用户的 sshd -T 上下文、实际 UFW/Fail2ban 动作与样本日志；确认未知和抽样边界可见，运行前后配置、服务和规则不变 |
| 可选扫描 | 内存不足/缺工具/过期库时明确停止；足够资源的隔离机上确认扫描范围、资源边界、Ctrl-C 和临时文件清理；用可信无害测试样本检查命中展示，不在业务机投放真实恶意程序 |
| 处置边界 | 扫描不自动删文件、隔离文件或停服务；修复菜单逐项确认且产生原模块记录；恢复仍校验 after 和连接条件 |

常规测试机上先升级、执行 `sudo vps-script audit`，按报告人工核实。无异常的 VMISS VPS 不因供应商传闻自动清理/重装；未检查 VPS 本身前不推断其安全状态。

## v0.8.0-dev 初始化向导演练

本地测试只运行演示流程、模拟后端和临时目录事务。真实修改需在可丢弃 VPS 单独验收：

| 项目 | 通过条件 |
| --- | --- |
| 入口与兼容 | 首页 `I` 与 `init` 进入同一流程；六类菜单、旧命令/JSON 不变；只读 `init` 的 `E` 不询问修改参数也不调用修改模块 |
| 选择与顺序 | 没有默认勾选或全自动执行；非法编号整次拒绝；选择顺序以目录为准；未选依赖不会偷偷补装 |
| 分步执行 | `E` 才进入原模块；仍有原检查、确认、SNAPSHOT 与第二 SSH 会话；完成后 `N` 才推进，下步仍待明确选择 |
| 跳过与退出 | `S` 跳过；步骤菜单 `Q`/`0` 或参数阶段 Ctrl+C 可退出；EOF 不自动继续；已有变更与记录保留，未执行步骤不生成成功记录 |
| 状态与结果 | 每次进入及执行前后读取当前状态；零返回取消不报成功；仅完成附属 UFW 操作不能标记 SSH 完成；开始/完成写记录失败需检查，不重复执行 |
| 恢复与重进 | `H` 打开现有历史恢复入口，范围/验证不放宽；返回刷新状态；再次进入重新选择，不凭历史跳过检查或自动续跑 |
| 安全栈 | UFW 与 Fail2ban 分开安装；首次 UFW 启用在 Fail2ban 安装前；现有 Fail2ban/Docker/nftables 等服务/规则仍保守停止，不自动关闭 |
| 故障 | 备份失败不修改；失败/中断保存材料且不自动推进；明确继续需 CONTINUE，重复执行需 RETRY；记录不可读不报完成 |
| 演示与发布 | `init --demo --experimental` 也不读取主机/历史或执行修改；下载、构包、安装清单均含 wizard.py；实际安装后仅走演示验证，不执行系统初始化 |

VPS 上建议先只选索引更新/时区等单项，核对记录与原模块结果；随后分别演练 SSH、UFW、Fail2ban，再考虑代理与转发。需要测试云防火墙、第二独立 SSH 会话、真实业务和重启持久化。向导不安装 Hy2 服务端；已有 UDP 监听之后才选择跳跃转发。断开连接后重新登录，用 `history` 与真实状态判定上一项结果，不根据进程消失直接重跑。

## v0.7.0-dev 备份与恢复验收

本地/CI 用临时目录和模拟命令验证持久记录；不要把新备份测试指向开发机或真实 VPS 的 `/var/lib/vps-script`。

| 项目 | 通过条件 |
| --- | --- |
| 修改前记录 | 创建目录/快照/写记录/容量检查失败时，实际修改回调零调用；取消不生成成功变更 |
| 存储安全 | 目录0700、文件0600；拒绝链接、非属主可写目录、无效ID/路径、损坏摘要、未知schema和超限内容；正文不出现在终端/JSON |
| 历史只读 | 查看空历史不建目录、不采集主机；详情只显示范围/摘要/结果；演示模式不读真实历史 |
| 状态语义 | prepared/running/completed/no_change/failed/interrupted/restored准确；命令完成不等于业务验证；完成记录写入失败不报告“未执行”也不自动重跑 |
| 选择恢复 | 仅completed、after完整且适配器支持的记录可选择；当前不等于after、环境不兼容或文件被外改时停止；恢复创建新记录，原记录避免重复恢复 |
| 清理与容量 | 最多100条/32MiB、单条2MiB、单文件256KiB；满后停止相关变更和恢复，不自动清理；失败/未完成/中断记录不得从菜单删除 |
| SSH/UFW/Fail2ban | SSH恢复保留当前端口并再次双会话验证；UFW拒绝删除当前SSH允许规则，删除操作仅审计；Fail2ban只恢复项目文件，不重建动态封禁 |
| 网络与系统 | BBR/调优按保存值且检查冲突；Hy2/swap仅完整状态正反恢复，异常态拒绝；swap不复制交换内容；时区不改NTP/时钟 |
| 外部变更 | APT安装/升级、3x-ui和外部脚本在原确认后要求SNAPSHOT；该值只表示用户声明未核实；所有这些记录均不可自动恢复；APT索引更新单独记录 |
| 故障注入 | 模拟修改中断、后快照失败、完成记录写入失败、恢复失败与并发；保留记录和原备份，不因为异常删除唯一恢复材料 |
| 安装包与升级 | 三个新模块位于下载/构包/安装清单；固定旧包用历史清单校验；当前包逐文件检查；升级前后的 backups 测试标记内容/权限不变。清除已验证的 CI 标记后，从安装目录隔离导入三个模块，验证 `history --json` 是合法空历史且没有创建记录 |

实际测试 VPS 需单独演练各支持的恢复，记录当前状态、所选ID、恢复前后服务/连接及是否依赖控制台。APT/3x-ui等外部快照仅在用户自行管理的备份系统中验证，不把输入SNAPSHOT作为快照存在的证据。

## 分阶段验证

| 阶段 | 具体检查 | 判定边界 |
| --- | --- | --- |
| 只读菜单 | 用普通用户和 root 分别运行状态查询；模拟依赖缺失、权限不足和非目标系统 | 不发起公网探测；未知不显示为正常 |
| 本地安装器 | 在干净系统预览、首次安装、旧版升级、遇到已有目标和中断；检查安装文件所有权与权限 | 未授权升级不覆盖；升级失败恢复或保留备份；卸载程序不等于恢复系统 |
| APT | 预览软件源、更新索引、模拟与选择安装；模拟锁、下载失败、已有配置和部分失败 | 目标和代理需提前说明；退出码不证明所有源或服务正常 |
| 3x-ui | 先审查固定脚本及其主要后续下载，再在全新测试系统交互安装；检查已有安装拒绝覆盖 | 预先披露 GitHub、软件源和上游公网 IP 查询服务；服务运行不代表公网访问或协议可用 |
| BBR / fq | 支持、模块未加载、模块不可用、配置冲突、重复执行、失败恢复和重启 | 分别读取运行时 TCP 值、接口队列与持久配置；不推断 Hy2 拥塞控制 |
| UFW | 先在已知可恢复的空环境测试当前端口放行、第二会话、主动取消、超时和规则变化；检查已有 nftables 空挂钩链、现有规则及其他对象会否阻止启用；测试启用过程和快照记录中断 | 确认主机与云防火墙分别生效；预检无法排除并发更改；瞬态恢复可能因缺少快照、状态变化、恢复命令失败或重启而无法执行，允许规则在回滚后保留 |
| SSH | 分别测试普通服务和 Ubuntu socket 激活；先添加新端口、独立登录，再单独关闭项目管理的旧端口；最后验证公钥、密码拒绝与恢复 | 不接受主机密钥异常；复杂 Match / Include 应停止；瞬态回滚不保证跨重启 |
| Fail2ban | 检查已有 jail 不被覆盖、systemd 日志可读、SSH 端口一致、测试误封与解封 | 服务 active 或 jail 存在不代表日志匹配或实际封禁有效 |
| Hy2 | 检查目标 UDP 监听、接口、端口冲突、IPv4/IPv6、nft 冲突、应用与恢复、重启 | 分别验证主机/云防火墙、客户端范围、多个跳跃端口和持续切换；规则存在不代表端到端可用 |

安装 3x-ui 或发起任何公网连接之前，明确目的地、请求类型、并发、超时和中止条件；仅对用户指定的测试机和服务操作。读取或分享日志前检查并遮盖 IP、认证信息和订阅地址。

## 必须记录的结果

- 每项的系统版本、架构、工具版本、命令退出状态、实际读取值、发生的警告和恢复结果。
- SSH 的新连接和认证方式是否真实验证；端口是否被主机及云防火墙分别允许。
- Hy2 的 IPv4、IPv6、服务端目标端口、至少多个跳跃端口、客户端切换和重启后行为。未测试的地址族或路径标为未知。
- 失败后是否出现部分修改、是否成功恢复，以及是否需要控制台干预。无法验证的恢复路径不能称为可靠保护。

## 版本发布条件

只有对应版本和架构上的只读功能、每个高风险模块、失败恢复与端到端测试均达到项目要求，才将该组合标为正式支持。测试机不能访问或环境不满足时，保留试验状态，不使用模拟结果替代真实验证。

- UFW DENY/OUT/来源限制与 IPv6 规则的保守状态判断，Fail2ban 树状计数。
- 调优不同参数重复执行、应用与自动恢复连续失败后的手动重试。
- 升级准备启动命令、替换目录、提交和恢复的故障注入；失败保留外部修改。
- 无 sudo 的 root 入口、合法 doctor JSON、演示预览零下载。
