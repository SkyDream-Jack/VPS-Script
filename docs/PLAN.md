# VPS 初始化与管理项目计划

> 状态：v0.4.0-dev 开发原型。这里描述目标与验收条件，不代表所有功能已经通过真实 VPS 验证。

## 0. 当前实现（v0.4.0-dev）

首版仍是 **SSH 终端面板**，不是 3x-ui 那样的 Web 面板；两者相互独立。当前已具备：

- 结构化只读状态：`status system|packages|panel|bbr|tuning|ssh|ufw|fail2ban|hy2|swap|timezone|dns|all`，支持 `--json`。
- 模块化操作：APT、固定版本 3x-ui、BBR/fq（含模块持久化）、内核网络调优（保守/代理/缓冲档）、SSH 端口/公钥、UFW、Fail2ban、Hy2 nftables 转发、swap、时区。
- 执行后自动显示对应只读状态；修改入口与只读入口分离，默认只读。
- 短安装入口、固定摘要和 `--upgrade` 升级；程序目录与系统配置分离。
- 审查记录见 [REVIEW.md](REVIEW.md)，优化调研与计划见 [OPTIMIZATION.md](OPTIMIZATION.md)。

尚未完成：真实 VPS 端到端验收、UFW 与 Fail2ban 在更多组合下的自动排序、3x-ui 更新/卸载、证书自动签发、Web 管理界面、批量机器管理。内核调优尚未做 A/B 性能验证。

## 1. 目标与边界

在新 VPS 上通过一个受版本控制、来源可审查的入口安装管理工具；之后通过菜单按需执行初始化、软件管理、安全配置、网络配置以及状态检查。管理工具的菜单与 3x-ui 自身的 Web 面板是两个不同的组件。

第一版使用 **SSH 终端菜单**，面向 **Ubuntu 和 Debian** 的单台 Linux VPS；项目维护在 [公开 GitHub 仓库](https://github.com/SkyDream-Jack/VPS-Script)。真实环境测试需要可恢复的测试 VPS。具体发行版版本和 CPU 架构只有经过对应验证后才列为正式支持；如未来需要 Web 管理界面，可在共享的功能层之上另做。不同系统或环境不满足前置条件时，应明确拒绝修改并解释原因。

首版不假设 VPS 是全新机器：已有 SSH、网络、规则、软件和 3x-ui 数据都可能需要保留。不能以工具安装成功、服务运行或配置文件存在，推断公网可访问或者客户端功能正常。

## 2. 目标使用体验

```text
VPS 管理菜单                            状态按实际检查显示

  1. 系统概览
  2. 网络设置：BBR / fq、Hy2 跳跃端口
  3. SSH 与安全：SSH、UFW、Fail2ban
  4. 3x-ui 安装与状态
  5. 系统软件：更新、升级、常用工具
  6. 常用工具：swap、时区、DNS
  7. 状态查询（单项 / 分组 / JSON）
  8. 工具维护
  9. 启用修改模式（默认只读）
  0. 退出
```

每项操作应有：当前状态、需要的前置条件、即将执行的变更、影响范围、结果、验证方式与恢复方式。高风险变更需要在对应步骤明确确认；命令执行失败时停止关联步骤并说明原因，不把部分完成显示为成功。只读查询与修改操作在入口和权限上清楚区分。

安装工具本身不等于执行所有初始化：让用户先查看当前环境，再按需选择功能；可在后续提供预设方案，但须逐项展示变更并处理每个前置条件。

## 3. 功能范围

| 模块 | 计划能力 | 应显示或核实的状态 |
| --- | --- | --- |
| 系统概览 | 查看系统、架构、内核、资源、服务与监听端口 | 可取得的实际状态；缺失或无权限明确标记未知 |
| 软件更新 | 检查软件源、更新软件索引、选择升级和安装常用工具 | 系统发行版、包管理器、命令结果、是否需要重启；不默认替换软件源 |
| 3x-ui | 检查已有安装；可选安装、更新及查看服务状态 | 官方来源和版本、服务状态、监听端口；保留现有数据库与配置 |
| BBR / fq | 检查支持情况、预览并有选择地修改配置、查看实际值 | 内核 TCP 拥塞控制、默认 qdisc 和相关接口的实际队列；与 Hy2 自身的拥塞控制分开 |
| 内核网络调优 | 保守/代理/缓冲三档，动态缓冲区，冲突检测与恢复，可选 TCP Fast Open | 实际 sysctl 值、项目配置/状态文件、内存与 conntrack；不以参数写入宣称提速 |
| SSH 安全 | 查看有效配置、分步修改 SSH 端口与身份验证方式 | 连接账户、实际监听端口、`sshd` 有效配置、服务或 socket 状态；不能仅凭公钥文件存在就判定可登录 |
| UFW | 检查当前防火墙和必需端口，再按需启用或增删工具管理的规则 | UFW 状态、IPv4 / IPv6、SSH 和业务端口；服务商防火墙需要另外检查 |
| Fail2ban | 按需安装和配置 SSH 防护，保留现有规则 | 服务、SSH jail、日志后端及封禁状态；配置和 UFW 分别检查 |
| Hy2 跳跃端口 | 输入已存在的 Hy2 UDP 目标端口、跳跃范围与接口；检查冲突，创建可持久化的项目专属转发规则 | IPv4 / IPv6、现有 NAT、防火墙、目标监听、持久化、客户端参数与实际跨网络测试 |
| 维护与恢复 | 查看项目自有变更、备份、恢复指定变更；将来支持工具更新 | 备份来源、时间、保护权限、冲突检测和恢复结果；不清空其他人的配置 |
| 常用工具 | swap 创建/移除、时区查看/设置、DNS 只读查看 | 项目文件、fstab 标记、timedatectl 结果；不覆盖其他 swap/DNS |
| 状态查询 | 单项、分组、全部只读状态，JSON 输出 | 未知/无权限与正常区分；执行后自动回显 |

可以后续加入证书到期检查、磁盘空间和系统日志查看、端口冲突检查等常用只读功能。证书自动签发、批量机器管理、流量监控、通用运维平台和 Web 管理面板暂不作为首个可用版本的交付条件。

## 4. 安全与可靠性原则

1. **检查先于修改。** 检查 OS、架构、权限、systemd、连接方式、当前监听与网络规则；不支持或无法可靠判断时停止，不猜测环境。
2. **高风险分步进行。** SSH 端口、SSH 认证、UFW 和 Hy2 转发应分别操作、分别验证；不要把它们做成一次不可观察的连续更改。
3. **保留访问路径。** 改 SSH 或启用防火墙前保留当前 SSH 会话、提示准备服务商控制台；先检查并允许实际使用的管理端口。改端口应先保留旧端口并从第二个会话测试新端口，再由用户单独决定是否关闭旧端口。
4. **公钥登录要实际验证。** 禁用密码和键盘交互认证前，检查针对目标用户和来源的有效 SSH 配置；引导从另一终端强制使用公钥建立新的连接并让用户确认。检测配置和公钥文件都不能替代外部登录验证。
5. **有超时恢复，但不承诺绝对安全。** 为 SSH / 防火墙高风险改动设计独立的定时回滚；测试超时、进程中断、重启及取消回滚。机器故障、管理服务不可用或云防火墙变化仍可能需要服务商控制台恢复。
6. **不覆盖不属于本项目的状态。** 备份目标文件，检查已有变更和文件身份；仅修改可识别的项目自有配置与规则。不清空全局防火墙、不覆盖现有 SSH 配置或 3x-ui 数据、不修改默认路由或 DNS。
7. **重复执行和恢复可预测。** 每个操作支持检查、预览、应用、验证和适用的恢复；重复执行不能重复追加规则。若已有人工修改与备份冲突，停止并提示，不自动覆盖。
8. **敏感信息最小化。** 私钥、面板密码、令牌、订阅链接不写入普通日志或 GitHub；必要的备份放本机受限目录。状态查询默认不显示敏感内容，日志默认本地保存并提示可能含有 IP 等敏感数据。
9. **诚实描述不可逆操作。** 软件包升级、第三方安装脚本、服务重启、内核更新及重启不保证能完整回滚；执行前说明并建议按需使用服务商快照。
10. **外部命令透明。** 软件源访问、第三方安装脚本、下载地址、版本、需要的权限和预计影响应提前说明；从可信官方来源获取且验证版本与完整性，不执行无法识别的远程内容。

## 5. 重要技术取舍

### 5.1 SSH 与系统差异

通过 `sshd -t` 检查语法，并结合 `sshd -T` 和目标用户、来源等条件检查实际生效值。检查 `Include`、`Match`、root 登录策略、系统的认证机制与密钥来源，不能只修改主配置文件后就宣布生效。Ubuntu 24.04 等系统可能由 `ssh.socket` 与 systemd generator 管理 SSH 监听，服务和 socket 的处理应针对实际运行模式实现和测试。见 [Ubuntu 24.04 发布说明](https://documentation.ubuntu.com/release-notes/24.04/)。

### 5.2 BBR、fq 与 Hy2

`net.ipv4.tcp_congestion_control` 是 Linux TCP 的设置；Hy2 使用 UDP/QUIC，其拥塞控制由具体实现和配置决定。`net.core.default_qdisc` 是默认队列设置，也不能单凭配置值证明每个接口的实际队列或网络表现。菜单需要分别展示事实与未知项，性能要靠实际测试。

### 5.3 Hy2 跳跃端口

跳端口需要客户端支持并使用对应范围；服务端需要接收或把这些 UDP 端口映射到实际监听端口，主机防火墙和云防火墙也必须允许相关流量。目标端口、范围、网络接口、IPv4/IPv6 和是否存在冲突都必须由检测与用户选择决定。优先采用可独立管理的专属规则；具体后端和持久化方式需在 UFW、iptables/nftables 与现有规则组合下测试通过后确定，不保存或清空整个机器的防火墙配置。

独立 Hysteria 服务和 3x-ui 中的实现不能直接视为同一种安装：独立 Hysteria 的新版文档提供 Linux 端口范围功能；3x-ui 某些版本的端口跳跃设置只负责生成或公布客户端范围，服务端仍需另配转发。具体以所用版本为准。参考 [Hysteria 端口跳跃文档](https://v2.hysteria.network/docs/advanced/Port-Hopping/) 与 [3x-ui 项目中的历史问题](https://github.com/MHSanaei/3x-ui/issues/4993)。

### 5.4 3x-ui 与供应链

只对接 [MHSanaei/3x-ui 官方项目](https://github.com/MHSanaei/3x-ui)。安装或更新前检测已有数据，明确将下载和运行具有 root 权限的第三方代码，先审查并锁定可追踪的版本，再核对上游提供的校验信息。下载文件与其同源校验值一致只能发现部分传输或意外损坏，不能单独证明上游没有被入侵。随机管理路径不是身份认证，面板访问还应考虑强密码、2FA、TLS、最小端口开放以及可选的反向代理。

## 6. 项目结构建议

初步采用 Python 3 标准库实现菜单、检测、操作编排和测试；用很小的 Bash 入口处理启动与依赖检查。Python 标准库便于清楚地处理结构化状态、参数、错误和自动化测试；也要考虑精简镜像可能缺 Python，并在安装依赖前说明软件源访问和权限。可根据目标系统的实际限制调整。

功能层与界面分离：每项能力提供检测、变更预览、执行、验证和适用的恢复；命令通过参数列表调用，避免拼接未受信任的 shell 命令。状态、日志和备份使用专属位置，权限最小化。检测命令尽量无需 root；必须提升权限的检查明确标注。

## 7. 分阶段实施和验收

| 阶段 | 工作内容 | 通过条件 |
| --- | --- | --- |
| 0. 方案确认 | 已确定 SSH 终端菜单、Ubuntu / Debian 和公开仓库；继续明确具体系统版本与验证安排 | 功能边界和验证环境清楚 |
| 1. 只读骨架 | 菜单、OS 和环境检测、权限提示、系统状态、项目结构与基础测试 | 非 Linux / 不支持系统不执行 Linux 修改；未知状态不冒充成功 |
| 2. 软件与服务 | 软件源检查、可选包更新与工具安装、3x-ui 检测和安全接入、只读验证 | 下载和影响透明；已有数据不被覆盖；失败可诊断 |
| 3. 低风险网络配置 | BBR / fq 的检测、预览、按需启用及恢复 | 实际生效值和不支持条件被正确展示，重复操作不会叠加 |
| 4. 访问安全 | SSH、UFW、Fail2ban 分步实现，保护访问及超时恢复 | 两个 SSH 会话、socket 模式、规则冲突、失败和超时回滚均经过隔离环境验证 |
| 5. Hy2 跳端口 | 独立管理 IPv4/IPv6 UDP 转发、持久化、状态与恢复 | 冲突检测、重启持久化、重复执行、客户端跨网络跳端口均经过验证 |
| 6. 发布维护 | 文档、版本化发布、安装及更新流程、变更记录 | 干净 VPS 可重复安装；来源与版本可追踪；真实验证范围如实披露 |

先完成方案与只读能力，再逐项增加修改能力；有真实 VPS 前，不将关键安全功能称为生产可用。

当前已有只读菜单与 APT、3x-ui、BBR/fq、SSH、UFW、Fail2ban、Hy2、swap 和时区的试验代码，默认关闭系统修改；还有短安装入口、固定摘要和 `--upgrade` 升级。GitHub Actions 在 Ubuntu 虚拟机和 Debian 容器中运行自动测试与只读查询，但测试以模拟为主，系统修改、恢复和真实 VPS 行为仍待验证，所有阶段均不能视为验收完成。

## 8. 测试策略

- 本地：单元测试、命令参数和解析测试；模拟不同系统、权限不足、依赖缺失与命令失败。测试不得修改开发机的真实网络与防火墙。
- 隔离 Linux 虚拟机：覆盖承诺支持的系统和架构，重点测试 systemd、SSH、UFW、Fail2ban、网络规则与重启；普通容器通常不能替代完整的网络和 systemd 测试。
- 可丢弃的真实 VPS：先确认控制台或救援方式和备份，测试双 SSH 会话、密码关闭、新端口、云防火墙、断线和超时回滚。逐项记录环境与结果，不在现有生产机上首次测试。
- Hy2：分别验证目标 UDP 端口与不同跳跃端口的连接、持续切换、IPv4/IPv6、重启后规则；服务状态或规则存在不等于客户端端到端成功。
- 维护：验证从旧版本升级、保留第三方配置、恢复前的冲突检查，以及卸载工具只移除其自有文件。
