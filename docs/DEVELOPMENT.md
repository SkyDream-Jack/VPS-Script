# 开发与验证说明

当前代码处于 v0.7.0-dev 开发阶段，不能用于生产 VPS。默认菜单可做只读查询；系统修改代码仅在显式传入 `--experimental`（或菜单内输入 `ENABLE`）时可选用，并且还要求 Ubuntu / Debian、root、交互式终端及逐次确认。演示模式始终不运行操作。

## 导航和状态约定

主菜单固定为六组：系统与软件、SSH 与安全、代理服务、网络与调优、诊断与测试、工具维护与恢复。首页首次进入与 `R` 刷新时采集只读摘要，显示采集时间；返回首页复用缓存。`M` 切换模式；带模块状态的子菜单自动显示短摘要，`S` 查看详细状态，成功操作后刷新对应模块。诊断与测试、第三方测试、工具维护与恢复不提供 `S`；诊断选项 1 进入按编号选择的状态查询菜单。完整状态报告及主动探测集中在诊断模块，外部脚本单独放在其子菜单。

界面复用结构化只读检查；不同视图的采集时刻可能不同，不能把旧缓存当作修改后的验证。未知、无权限和缺少依赖不能被概括成“正常”。首页刷新和模块摘要不运行 ICMP、测速或外部脚本，也不能用服务 active 代替公网/协议验证。命令行 section、别名以及 JSON schema 不随此次菜单调整改变，`status network` 仍是 BBR + 调优 + Hy2。

维护模块保留原有 1–4 项，新增 `5 备份记录与恢复`，可查看历史、选择详情、请求恢复和明确删除记录；这个子菜单不提供 `S`。新增 CLI `history [ID] [--json]` 与 `restore ID --experimental`，原有 status section/别名及 JSON schema 不变。初始化向导与整机恢复仍未实现，现有模块的前置检查、确认和失败回退继续保留。

## 软件管理试验范围

- 可选：更新现有 APT 软件源索引、升级已安装的软件包、安装预设的基础 / 网络 / 查看 / 安全工具。
- 不修改软件源配置，不执行 `full-upgrade`、`autoremove` 或包卸载；安装和升级通过 `--no-remove` 在需要删除软件包时中止。
- 升级和安装先执行 APT 的模拟模式，模拟不持锁，实际执行时系统状态可能已变化。APT 或已有配置的钩子可能产生额外影响；用户取消时不执行正式修改。
- 网络目标取决于现有软件源、APT 配置、代理和重定向。界面只显示默认源文件中可识别的 HTTP(S) 主机，省略 URL 凭据和路径；它不能证明显示了所有目的地。
- 不继承 `APT_CONFIG`，避免调用者改变 APT 的配置目录、钩子和来源；代理变量会保留但不显示。
- 软件包操作持久记录动作与结果，但不能通过本工具完整回滚。索引更新不要求快照声明；安装/升级在原有确认后要求输入 `SNAPSHOT`，仅记录用户自报已准备外部备份，工具不核实。APT 退出码为 0 不证明所有源都已成功刷新、所有服务正常或不需要重启。

## 其他试验功能的边界

- **3x-ui：**固定官方版本和安装脚本摘要，现有安装会被拒绝覆盖。上游脚本会执行 root 操作并查询公网 IP；证书等可选步骤有额外网络与信任边界，见 [接入记录](3X-UI-AUDIT.md)。只读取面板端口/路径，不读取账户、密码或数据库。
- **BBR / fq：**仅写入项目专属 sysctl 文件，记录原值，发现冲突或外部修改时停止。内核尚未列出 `bbr` 时会先说明并在用户确认后尝试加载 `tcp_bbr`，需要时写入 `/etc/modules-load.d/vps-script-bbr.conf`；模块不会自动卸载。重启后的生效情况未验证。
- **SSH：**只处理标准 `sshd_config.d` 布局，遇到 `Match`、其他 Include、已有多因素认证或不可判断的设置会停止。新增端口先保留旧端口；可在修改前请求 UFW 放行新端口；只有旧端口由本项目管理、当前连接使用其他端口时才能尝试关闭。仅公钥认证会影响所有账户，菜单会列出可登录账户并要求输入 `ALL USERS`；当前只验证执行账户的公钥，其他账户需自行确认。 如果选择保留 root + 22，只执行“仅公钥认证”，不执行端口变更；工具不会自动禁用 root，也不会把 `PermitRootLogin yes` 改成 `prohibit-password`，但密码/键盘交互关闭后 root 实际只能使用密钥。
- **UFW：**首次启用前要求默认入站策略为 `deny`，并为当前 SSH 端口添加允许规则；遇到其他防火墙服务、现有 nftables 规则或挂钩链、无法识别的 nftables 对象时停止。超时后会尝试恢复到此前未启用状态，但预先加入的允许规则会保留；如果启用过程中断而状态快照未完成、规则被其他工具修改或恢复命令失败，自动恢复可能不执行或失败。
- **Fail2ban：**为 SSH 创建项目专属 jail，已有系统 `sshd` jail 不被覆盖；UFW 已启用时优先使用 `ufw` 封禁动作。SSH 端口变化后只更新项目 jail 的 `port` 行；实际日志匹配、封禁和解封需单独测试。
- **Hy2：**只管理项目专属 nftables 表和 systemd 单元；发现已有 NAT 规则、旧版 NAT 表或 UDP 监听冲突时停止。可选在 UFW 已启用时放行 UDP 范围和目标端口；不会修改云防火墙或客户端。应用失败时会尝试清理项目文件/规则，无法确认时保留状态供人工恢复。
- **内核网络调优：**只写 `/etc/sysctl.d/91-vps-script-tuning.conf` 和项目状态文件；不改 BBR/default_qdisc、不换内核、不做 qdisc/HTB 整形、不改 initcwnd/DNS/转发/RPS/MSS。保守/代理/缓冲三档；缓冲档按内存和用户输入的预期带宽/RTT 估算，不是实测。其他 sysctl 文件设置不同值时会停止；应用失败按快照回滚，外部修改后拒绝恢复；配置尚未生成的部分应用可根据有效快照重试恢复。切换档位或参数需先恢复旧调优。参数改变不代表性能一定提升。
- **测试与体检：**内置机器/网络/线路/带宽测试只运行固定命令；带宽测试使用 Cloudflare 单线程下载并明确消耗流量。外部 NQ/TQ/IPQuality/NetQuality/YABS 不在本项目源码内，按各自许可证运行；固定 URL 白名单、先下载并显示 SHA，需要修改模式、`RUN` 及外部备份声明 `SNAPSHOT` 确认，持久记录后才创建临时文件并执行。独立预览选项显示前 120 行，不执行；预览与运行是两次下载。上游脚本/rootfs/二进制未固定摘要，可能安装软件、访问大量第三方节点并上传 IP/结果；只在测试 VPS 使用。
- **swap / 时区：**swap 只管理 `/swapfile-vps-script` 和带标记的 fstab 行，已有其他 swap 时停止；时区只调用 `timedatectl set-timezone`，不会修改 NTP/时钟。DNS 仅只读展示。

例如，在已准备好控制台恢复、快照和测试网络的**可丢弃测试机器**上，开发者可以启动试验模式：

```bash
./vps-admin --experimental
```

该命令本身打开菜单；选择实际操作并确认后才会运行。不要在重要 VPS 上测试。

## 现有备份与恢复覆盖

统一记录由 `backup.py` 管理，访问安全和网络资源分别由 `backup_access.py`、`backup_network.py` 提供固定适配器。备份发生在已确认的操作之前；失败会阻止实际修改。记录持久化后、实际操作前再核对当前状态与 before 一致；工具内串行锁不能阻止外部 root 工具同时修改。记录保存在 `/var/lib/vps-script/backups/<ID>/record.json`，不包含可执行命令模板；恢复通过固定适配器调用，不能把用户输入或记录中的任意路径交给 shell。

| 模块 | 保存和恢复的范围 | 不能自动恢复的情况与限制 |
| --- | --- | --- |
| SSH | 项目 `00-vps-script.conf` 前后内容/权限及环境校验信息；可恢复旧文件或删除当次新建文件 | 当前必须匹配记录 after，其他 sshd 配置不能漂移；恢复目标必须保留当前 SSH 端口，使用新的 180 秒事务和第二会话 `VERIFIED`。可能重新启用密码认证；不备份账户私钥，不保证瞬态恢复跨重启 |
| UFW | 记录规则/状态；安全识别的新增简单 allow 可逆向删除，首次 inactive→active 可请求回到 inactive | 不能删除包含当前 SSH 端口的规则；首次启用恢复保留新增 allow 且会关闭防护。删除规则仅保存记录、不能自动按原顺序重建；不 flush/覆盖全表，不改云防火墙。规则文件计数器变化也可能使严格 after 匹配失败而拒绝恢复 |
| Fail2ban | 保存项目 jail 文件，允许恢复或移除该文件 | 仅在没有其他活动 jail、历史端口匹配当前 SSH、banaction 匹配当前 UFW 栈时重载；不恢复动态封禁 IP/计数/剩余时间，unban 仅审计，不自动重新封禁 |
| BBR / fq | 保存固定白名单的运行值和项目配置；可撤销应用或恢复操作 | 当前必须等于 after，其他相关 sysctl 配置不能漂移或冲突；历史算法不可用时拒绝，不卸载已加载的 tcp_bbr 模块，也不还原接口实际 qdisc |
| 内核调优 | 保存原运行值和项目配置，按保存值恢复，不重新估算带宽/RTT 参数 | 当前必须等于 after，外部冲突时停止；不是内核替换、qdisc 整形或完整网络恢复 |
| Hy2 跳跃端口 | 完整 active+enabled 项目转发与完全未配置之间可正反恢复 | 重建时重新检查接口、监听和 NAT；部分/失败/自定义 inactive 状态仅保留材料。UFW 放行是独立记录，不随 NAT 恢复，不恢复服务端程序/客户端/云防火墙 |
| swap | 合法大小、0600 权限、独立 fstab 标记且 active 的项目 swap 与未配置之间可正反恢复 | 不能存在其他 swap；重建的是空 swap，不备份交换数据，不做整盘恢复；异常或不活跃状态需人工处理 |
| 时区 | 保存有效时区，经 `timedatectl` 校验后恢复 | 不恢复系统时钟、NTP 配置或原 localtime 文件布局。DNS 仍只读 |
| APT / 3x-ui / 外部脚本 | 记录固定动作、版本/入口摘要、结果和用户的外部备份声明 | 标记不可自动恢复；声明不代表工具核实了快照。索引更新无 SNAPSHOT gate；其余安装/升级/第三方脚本在原确认后要求 `SNAPSHOT`。不保存环境、完整 stdout 或面板凭据 |
| 工具自身升级 | 安装器继续使用独立的旧程序/启动器暂存事务，保留统一记录目录 | 失败恢复或保留暂存材料；成功后清理暂存，不提供程序版本历史恢复；不会撤销 `/etc`、`/var` 中的系统变更 |

所有历史恢复都要求当前受管理状态与所选记录的 after 匹配；这不是任意选一条旧记录强行覆盖整机。恢复本身创建关联记录，成功后将原记录标为 restored，避免同一记录重复恢复；恢复也可能失败，必须读取新记录和实际状态。

### 记录生命周期与存储限制

- 状态分为 prepared、running、completed、no_change、failed、interrupted、restored。completed 仅表示命令完成并取得操作后记录，不证明外部连接、服务或协议可用。
- 只有 completed、有完整 after 且适配器允许的记录可请求恢复。failed/interrupted 保留材料，先核对原模块回退结果，不自动覆盖系统。
- 完成记录写入失败时，操作可能已经执行；必须检查状态，不能因为返回失败就自动重试。SIGKILL、断电等可能留下 running 记录，需要人工核查。
- 目录只允许属主访问，文件 `0600`；拒绝不安全权限、链接、无效 ID 和损坏记录。只读列表/详情不创建目录，也不运行主机检查；默认输出仅含摘要，不展示备份配置正文。
- 单文件上限 256 KiB、单记录 2 MiB、总量 32 MiB、最多 100 条。为下一条预留空间，不保证可以正好用满；容量不足阻止新操作和需要新记录的恢复，不自动清理旧记录。
- 菜单只能明确删除 completed、no_change、restored 记录，需 `DELETE <ID>`；失败/中断/未完成记录保留供人工处理。删除不会改变系统配置，也不会撤回历史操作。

用户仍需为无法覆盖的整机/应用数据准备服务商快照或独立备份；自动备份范围之外的内容不能靠当前记录恢复。下一阶段重点为真实恢复演练、兼容性与保留策略，再考虑初始化向导，见 [项目计划](PLAN.md#下一阶段备份与初始化计划)。

## 本地测试

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
```

测试中的 APT、SSH、防火墙、Hy2 和 swap 调用使用模拟对象，不运行真实的系统软件修改，不访问软件源。安装器事务直接在临时目录测试文件切换、回滚和锁，不使用开发机的安装目录。启动脚本和演示模式可以在 macOS 上验证；实际 Linux 只读检测、系统修改和服务行为需在相应环境另行验证。

导航回归应覆盖六个入口、子菜单返回、`M`/`R`、只读模式与演示模式、外部测试子菜单，以及旧命令/JSON 兼容性。纯粹查看状态不得触发任何变更或公网探测。

## 自动检查

GitHub Actions 在 Ubuntu 虚拟机及 Debian 容器中运行单元测试与只读系统查询，结果以对应提交的运行记录为准。这些测试以模拟为主；Debian 容器不能证明 systemd、SSH、防火墙、重启持久化或跨网络协议可用。高风险功能需要带有控制台访问的独立虚拟机和 VPS 端到端测试。
