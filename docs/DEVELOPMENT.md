# 开发与验证说明

当前代码处于开发阶段，不能用于生产 VPS。默认菜单可做只读查询；系统修改代码仅在显式传入 `--experimental` 时可选用，并且还要求 Ubuntu / Debian、root、交互式终端及逐次确认。演示模式始终不运行操作。

## 软件管理试验范围

- 可选：更新现有 APT 软件源索引、升级已安装的软件包、安装预设的基础 / 网络 / 查看工具。
- 不修改软件源配置，不执行 `full-upgrade`、`autoremove` 或包卸载；安装和升级通过 `--no-remove` 在需要删除软件包时中止。
- 升级和安装先执行 APT 的模拟模式，模拟不持锁，实际执行时系统状态可能已变化。APT 或已有配置的钩子可能产生额外影响；用户取消时不执行正式修改。
- 网络目标取决于现有软件源、APT 配置、代理和重定向。界面只显示默认源文件中可识别的 HTTP(S) 主机，省略 URL 凭据和路径；它不能证明显示了所有目的地。
- 软件包升级无法保证回滚。APT 退出码为 0 不证明所有源都已成功刷新、所有服务正常或不需要重启。

## 其他试验功能的边界

- **3x-ui：**固定官方版本和安装脚本摘要，现有安装会被拒绝覆盖。上游脚本会执行 root 操作并查询公网 IP；证书等可选步骤有额外网络与信任边界，见 [接入记录](3X-UI-AUDIT.md)。
- **BBR / fq：**仅写入项目专属 sysctl 文件，记录原值，发现冲突或外部修改时停止。内核尚未列出 `bbr` 时会先说明并在用户确认后尝试加载 `tcp_bbr`；模块不会自动卸载。重启后的生效情况未验证。
- **SSH：**只处理标准 `sshd_config.d` 布局，遇到 `Match`、其他 Include、已有多因素认证或不可判断的设置会停止。新增端口先保留旧端口；只有旧端口由本项目管理、当前连接使用其他端口时才能尝试关闭。仅公钥认证需要先人工验证独立连接，并再次验证修改后的新连接：禁用 SSH 连接复用、强制使用公钥，并核对主机密钥。还应单独检查密码和键盘交互认证是否被拒绝；配置值和公钥连接成功不能替代这项检查。
- **UFW：**首次启用前为当前 SSH 端口添加允许规则；遇到其他防火墙服务、任何现有 nftables 规则或挂钩链、无法识别的 nftables 对象时停止，不仅凭链名判断归属。空的挂钩链也可能有 `drop` 默认策略。预检会在启用前再次执行，但无法阻止其他工具并发更改规则。超时后会尝试恢复到此前未启用状态，但预先加入的允许规则会保留；如果启用过程中断而状态快照未完成、规则被其他工具修改或恢复命令失败，自动恢复可能不执行或失败。单独开放端口会允许任意来源，云防火墙仍需另行管理。
- **SSH 和 UFW 的恢复定时器：**目前使用 systemd 瞬态定时器，进程断开时可能仍能运行，但不能保证跨重启；定时器在变更前启动，提示验证时剩余时间可能少于 180 秒。务必准备服务商控制台。恢复脚本和竞争处理只在本地模拟，尚未经过真实断线或重启验证。
- **Fail2ban：**为 SSH 创建项目专属 jail，现有活动 jail 不被覆盖。实际日志匹配、封禁动作和管理用户可用性需单独测试；修改 SSH 端口后需再次检查 jail 端口。
- **Hy2：**只管理项目专属 nftables 表和 systemd 单元；发现已有 NAT 规则、旧版 NAT 表或 UDP 监听冲突时停止。不会自动修改 UFW、云防火墙或客户端；目标 UDP 端口、跳跃范围、重启持久化和实际跳跃连接需逐层验证。

例如，在已准备好控制台恢复、快照和测试网络的**可丢弃测试机器**上，开发者可以启动试验模式：

```bash
./vps-admin --experimental
```

该命令本身打开菜单；选择实际操作并确认后才会运行 APT。不要在重要 VPS 上测试。

## 本地测试

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
```

测试中的 APT 调用使用模拟对象，不运行真实的系统软件修改，不访问软件源。启动脚本和演示模式可以在 macOS 上验证；实际只读检测和试验功能需在 Linux 上另行验证。

## 计划中的自动检查

项目包含 GitHub Actions 配置，计划在 Ubuntu 虚拟机及 Debian 容器中运行单元测试与只读系统查询；它尚未运行。Debian 容器不能证明 systemd、SSH、防火墙、重启持久化或跨网络协议可用。高风险功能需要带有控制台访问的独立虚拟机和 VPS 端到端测试。
