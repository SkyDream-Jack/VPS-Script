# 3x-ui 安装脚本接入记录

本记录针对官方项目 `MHSanaei/3x-ui` 的 `v3.11.0` 安装脚本，使用提交 `c621ba9014a6aa21fd7c9ecf45655e44e24ebf13` 的文件。脚本 Git blob 为 `dd67e6c0935f5f1f1858ea5b4cef24107e91dc69`，下载文件的 SHA-256 为 `9684bae4f769b2127fcceceb4f200045657381311867529e6ba76c6b58e2825d`。固定值是本项目维护的审核锚点，更新版本需要重新检查，而不是自动跟随上游 `latest`。

检查范围为安装入口、依赖、网络地址、安装目录、服务、证书和 Fail2ban 的主要分支；不是对整个上游项目或所有后续版本的完整安全审计。来源：[固定提交的官方安装脚本](https://github.com/MHSanaei/3x-ui/blob/c621ba9014a6aa21fd7c9ecf45655e44e24ebf13/install.sh)。

## 已发现的行为

- 脚本要求 root。Ubuntu/Debian 上会执行 `apt-get update` 并安装 cron、curl、tar、tzdata、socat、ca-certificates、openssl；会下载发布包、解压文件，并启用或启动 systemd 服务。
- 获取发布包和管理脚本使用 `github.com`、`raw.githubusercontent.com`，可能遇到重定向；启用其他交互选项后还可能访问其他服务。
- 安装后会依次访问最多六个公网 IP 查询服务来显示面板访问地址：`api4.ipify.org`、`ipv4.icanhazip.com`、`v4.api.ipinfo.io`、`ipv4.myexternalip.com`、`4.ident.me`、`check-host.net`。每次最多等待 3 秒，成功后停止。即便设置了 `XUI_SERVER_IP`，脚本仍先尝试这些服务。
- 在安装流程中选择证书签发时，脚本可能从 `get.acme.sh` 获取并运行代码，且需要相应域名或 IP、网络及端口条件；选择 PostgreSQL 时可能新增第三方软件源或访问外部数据库。具体依赖选择由上游交互流程决定。
- 上游默认可能安装并配置 Fail2ban 供面板的 IP 限制功能使用。本项目接入时设置 `XUI_ENABLE_FAIL2BAN=false`，由独立的安全模块负责；面板的 IP 限制功能可能因此不可用，直到用户按需配置。
- 上游在发现已有安装目录时会停止服务、删除和重建程序目录，异常中断后可能无法启动。因此本项目的首次安装入口遇到现有目录、数据库或服务文件时拒绝覆盖；现有安装的更新流程需要另行设计和测试。
- 此版本的 ACME 端口检查在 `ss` / `netstat` 的 awk 分支中存在疑点：匹配后 `END` 仍返回失败。仅依据静态代码和本地 awk 验证，不能假定它会正确提示端口占用；证书签发前应独立检查端口。
- 上游验证发布包旁的 `.sha256`；如果对应文件返回 404，脚本会警告并跳过。与发布包同源的校验值也不能单独证明上游没有被入侵。
- 上游会在终端显示或写入面板凭据。不要把输出、凭据文件、数据库或订阅链接上传到公开仓库。

## 本项目的试验接入边界

下载前说明网络目标和影响；从固定提交下载，并先检查文件大小与上述 SHA-256。执行时使用固定参数和受控环境，禁用上游自动 Fail2ban 配置，保留上游交互式选择。安装结果只能说明脚本的退出情况；面板的监听、TLS、访问权限和外部可达性需要另外验证。

当前接入代码仅供隔离测试，未在真实 Linux 虚拟机或 VPS 验证；不能用于生产。它没有自动更新现有 3x-ui，也不会自动开放管理端口。
